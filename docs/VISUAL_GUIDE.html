Architecture

ARCHITECTURE.md

Entry points converge before execution. Capabilities own turns; tools are selected inside them.

Decisions

why, not just what

Each entry records the rejected option, because the rejection is what future work must not undo.

1

Merge upstream, never rebase it

19 local commits stay intact; each release lands on a sync branch and records which side won every collision.

2

Export in the browser

Rejected a server-side document service: it added Python dependencies and broke whenever upstream moved the API.

3

Preferences in user-owned JSON

A generated catalog gets overwritten by updates; model_preferences.json survives and stays inspectable.

4

One interpreter path

The installer and runtime share _env_bin_dir, so pip and the entry point can never disagree.

5

Apache-2.0 stays

PolyForm cannot be applied to a derivative of Apache-2.0 code. This is a documented exception to the protocol default.

Landmines

do not "clean up"

These look redundant until the exact platform or update that needs them arrives.

Taking upstream wholesale in custom subsystems

Never resolve web/lib/export/ or deeptutor/services/subagent/ with --theirs. Upstream does not know these features exist.

Windows npm shims at the prefix root

Windows npm writes .cmd at the prefix root, not bin/. Removing the special case makes every CLI app look missing.

Duplicated interpreter-path math

An inline path expression drifts from bin_dir; installation succeeds and execution fails later, on the learner's machine.

Treating .env as configuration

Runtime settings live in data/user/settings/. A feature that reads .env works locally and fails in every packaged install.

Re-wrapping normalized LaTeX

Wrapping an already-wrapped matrix breaks the whole message's rendering. The normalizer must stay idempotent.

Assuming CREATE_NO_WINDOW exists

Stripped Python builds lack the constant. Keep the getattr fallback or the app fails to launch with a traceback.
